## Build box (rx)

- Run heavy or Linux-only commands (cargo build/test/nextest/clippy on more than a small crate, cargo-fuzz, `tlc`, benchmarks, `docker build`) on the build box: `rx run -- <cmd>`. It syncs this worktree and exits with the command's code. Prefer `rx run` for anything that finishes within your tool timeout; it's the warmest and fastest. For quick looks (`uptime`, `docker ps`), use `rx sh -- <cmd>`: no sync, no queue. If your harness blocks `rx sh` (e.g. worktree-isolated subagents), use `rx run -- <cmd>`; it waits behind any running `rx run` in the worktree. Run every rx call from your worktree, repeating `cd <worktree> &&` since the harness may reset the cwd (`rx wait`, `logs` and `kill` need the directory you submitted from).
- Use `rx submit <name> -- <cmd>` only for jobs that may outlive your timeout, then `rx submit ... && set -o pipefail && timeout 570 rx wait <name> | tail -50` with your shell tool's timeout at its max (e.g. 600000 ms). Never pipe or silence `rx submit`, and keep the `&&` before `rx wait`: otherwise a refused submit shows the old job's result. Never poll `rx ps`, sleep-loop or use Monitor loops to wait. Submitted jobs run on a snapshot taken at submit time. Reuse a finished job's name to rerun incrementally; a fresh name builds cold unless `rx run` warmed the worktree, so don't fan out many fresh names. Agents sharing one worktree use `rx submit <own-name>`, not `rx run`: runs queue per worktree, and `rx wait run` follows the newest run, which may be another agent's.
- rx jobs take no local build locks and no parallelism caps (`-j`, TLC `-workers 2`, `--test-threads`); those rules are for the Mac. Use the whole box: TLC `-workers auto`, cargo defaults, and as many jobs at once as you need. A test timeout under heavy load (`rx sh -- uptime`) is no result: rerun those tests. Give long `docker run`s `--memory`, `--cpus` and `--name`, and run them in the foreground of an `rx submit` job (no `-d`) so `rx wait` covers them; containers sit outside rx's job controls, so `rx kill` leaves them running: stop yours with `rx run -- docker kill <name>`. All containers share one cap of 70% of RAM (check `rx sh -- free -g`): keep the total `--memory` of your concurrent containers under that, or the biggest gets OOM-killed. A process killed at a memory cap (`--memory`, or the shared job cap) may only show its tool's own error or one failed test; check `rx sh -- journalctl -k --since -1h -g 'Killed process'`. A `No such file` on a `target/` next to `mbx[gc]: ... under the 99.0 GiB minimum` in a job log means the cache GC removed it: rerun, and read build outputs inside the job that built them. Never hold a local lock while waiting on an rx job.
- Quote the job command (`'...'`) so `~` and `$HOME` expand on the box, not the Mac. Keep job output on stdout (`| tee`, not `>file`). Start piped commands with `set -o pipefail;`. Chain setup steps with `&&`. `.git` isn't on the box: use `patch -p1`, not `git apply`.
- If a run was cut off by a timeout or sent to the background (by you or your harness), it is still running: don't restart it. Wait with `timeout 570 rx wait <name>` (`run` for `rx run`; set the tool timeout to 600000 ms, or the call is cut at 120 s; in Codex set `yield_time_ms` to the maximum, 30000 on `exec_command`, and rerun the wait each time it yields rather than polling `rx logs`), again if it times out, not sleep, polling or Monitor loops, even if the harness suggests them. Don't end your turn on a promised notification: a delegated agent never gets it.
- Linux artifacts stay on the box. Use `rx pull <path> [job]` only for data. Never put secrets in commands or in un-ignored files. rx syncs every non-ignored file: for a clean set, run it from a fresh `git worktree add` checkout, never from a patched copy of `rx` (the box is your own machine, so Mac paths and names there are not leaks). Put big scratch (clones, downloads, and `TMPDIR` for tools that copy the tree, like cargo-mutants without `--in-place`) under `~/rx/scratch/<name>`, not the box `$HOME` or `/tmp`. For any cargo command that compiles near-workspaces (tests, check, clippy), prefix the job with `NEAR_SANDBOX_BIN_PATH=$HOME/.near/near-sandbox-2.14.0/Linux-x86_64/near-sandbox` (else `could not create download path`).
- Before finishing, `rx kill` jobs you no longer need and report any still running (`rx ps`).
