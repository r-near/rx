## Build box (rx)

- Run heavy or Linux-only commands (cargo build/test/nextest/clippy on more than a small crate, cargo-fuzz, `tlc`, benchmarks, `docker build`) on the build box: `rx run -- <cmd>`. It syncs this worktree and exits with the command's code. Prefer `rx run` for anything that finishes within your tool timeout; it's the warmest and fastest. For quick looks (`uptime`, `docker ps`), use `rx sh -- <cmd>`: no sync, no queue. If your harness blocks `rx sh` (e.g. worktree-isolated subagents), use `rx run -- <cmd>`; it waits behind any running `rx run` in the worktree.
- Use `rx submit <name> -- <cmd>` only for jobs that may outlive your timeout, then `rx submit ... && set -o pipefail && timeout 570 rx wait <name> | tail -50` with your shell tool's timeout at its max (e.g. 600000 ms). Never pipe `rx submit` itself (it hides a refused submit), and never poll `rx ps`, sleep-loop or use Monitor loops to wait. Submitted jobs run on a snapshot taken at submit time. Reuse a finished job's name to rerun incrementally.
- rx jobs take no local build locks and no parallelism caps (`-j`, TLC `-workers 2`, `--test-threads`); those rules are for the Mac. Use the whole box: TLC `-workers auto`, cargo defaults, and as many jobs at once as you need. Give long `docker run`s `--memory`, `--cpus` and `--name`; containers sit outside rx's job controls, so `rx kill` leaves them running: stop yours with `rx run -- docker kill <name>`. All containers share one cap of 70% of RAM (about 165 GiB): keep the total `--memory` of your concurrent containers under that, or the biggest gets OOM-killed. A process killed at the `--memory` cap may only show its tool's own error; check `rx sh -- journalctl -k --since -1h -g 'Killed process'`. Never hold a local lock while waiting on an rx job.
- Quote the job command (`'...'`) so `~` and `$HOME` expand on the box, not the Mac. Keep job output on stdout (`| tee`, not `>file`). Start piped commands with `set -o pipefail;`. Chain setup steps with `&&`. `.git` isn't on the box: use `patch -p1`, not `git apply`.
- If a run was cut off by a timeout, it is still running: use `rx ps` and `rx wait run`. Don't restart it.
- Linux artifacts stay on the box. Use `rx pull <path> [name]` only for data. Never put secrets in commands or in un-ignored files. Put big scratch (clones, downloads) under `~/rx/scratch/<name>`, not the box `$HOME` or `/tmp`. For near-workspaces tests, prefix the job with `NEAR_SANDBOX_BIN_PATH=$HOME/.near/near-sandbox-2.14.0/Linux-x86_64/near-sandbox` (else `could not create download path`).
- Before finishing, `rx kill` jobs you no longer need and report any still running (`rx ps`).
